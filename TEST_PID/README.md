# 恒流 PI / PID 独立调参固件

目标 `YLD_Cup_CCPIDTune`：在实际负载上测量响应，计算一组 **PI/PID 初始系数**，再用恒流阶跃比较。上电输出关闭，按键才启动；结束、手动停止、保护触发都会关输出。没有烧录或实物测试，不能把下面算法测试中的数字当作本板系数。

应用在 `cc_pid_main.c`，与硬件无关的算法和可移植的 PID 在 `cc_pid.c`，标定、限制和节拍在 `cc_config.h`。复用 `TEST_MODULES/test_board.c` 初始化 ADC/DAC/按键，ADC 使用与主程序相同的 4 次均值及切通道弃首样。没有修改主程序的恒流占位代码。

## 烧录和接线

在 CLion 复制运行配置，将 Target 改为 **YLD_Cup_CCPIDTune**，然后构建、下载；或：

```bash
cmake --build --preset Debug --target YLD_Cup_CCPIDTune
```

产物：`build/Debug/TEST_PID/YLD_Cup_CCPIDTune.elf`。烧回 `YLD_Cup` 可恢复原主固件。系数和波形只保存在 RAM，复位前记录结果。

1. 先把电压、电流的**实测标定值**同步到 `cc_config.h`。`CC_IOUT_SCALE` 对应主程序的 `IOUT_GAIN_TRIM/(IOUT_SHUNT_OHM*INA199_GAIN)`，零偏用 `CC_IOUT_OFFSET`；输入电流同理。默认仍是理论值。
2. 使用已有的 PA4 DAC、PB0 输出电流、PA6/PA7 电压采样、PA1 输出 MOS，以及 PB15/PB14/PB13 三键和 OLED。接线顺序见资料目录的《代码复核与接线顺序》。Q3 切负端，仪器接地不能把输出负端直接并到系统地。
3. 接限流的主输入电源，输入测量点需达到 13V，默认可沿用 16V 输入。采用功率电阻或电子负载 **CR 电阻模式**。不要用电子负载 CC 模式与本板恒流环互相调节。
4. 默认测 1.0A、验证最高 1.1A；例如 10Ω 负载对应约 10～11V、10～12.1W，应选有足够散热余量的功率负载（如 25W 等级）。其他目标须按 `I*R`、`I²*R` 核对，本固件输出电压上限为 12V。不要接短路负载。

## 按键和测试过程

| 状态 | K1 / PB15 | K2 / PB14 | K3 / PB13 |
|---|---|---|---|
| IDLE | 目标 +0.1A | 目标 -0.1A | 短按松手开始识别 |
| 测试运行 | 忽略 | 忽略 | 按下立即请求关断 |
| READY / 结果 | 切 PI/PID | 系数倍率 0.25→0.5→1.0→0.25 | 短按松手开始阶跃验证；长按 800ms 清结果回 IDLE |
| FAULT | 忽略 | 忽略 | 短按松手解除到 IDLE；再次启动需另按一次 |

自动识别的步骤：

1. DAC 先置 3.1V，输出保持关闭至少 400ms；Vout 降至 4V 以下、测得 Iout 不大于 0.05A 才允许合闸。超过 3s 仍不满足会报范围错误。
2. 从最低输出档慢慢增加输出：DAC 每 100ms 减少 5mV，直到电流达到设定值，记录工作点 `bias`。默认目标范围 0.4～1.5A；DAC 饱和、起始电流已经超过目标或没有足够扰动余量都会停止。
3. 在工作点两侧施加 DAC ±50mV 的继电器扰动，电流迟滞 ±3mA。丢弃前 2 个周期，采集后续 6 个完整周期。寻找工作点最多 60s，任一半周期超过 5s 不过阈值会停止。
4. 检查周期不少于 120ms、电流半幅至少 15mA、升流档占空比 20%～80%，并检查周期和半幅各点相对均值偏差不超过 20%。不合格不会给出自动系数。
5. 合格则关输出，显示默认 **0.25 倍 PI 系数**。屏上的 `KP/KI/KD` 已乘倍率，可直接记录，**不要重复乘倍率**。`TU/s` 为周期秒数，`KU` 为估计增益。

运行期间 OLED 显示 `DISPLAY PAUSED`，软件 I²C 刷新暂停以维持 10ms 采样/控制节拍。实时数据可在调试器 Watch 查看 `cc_measurement`、`cc_status`，`cc_max_gap_ms` 显示本次有输出时的最大采样间隔。不要在带输出测试时打断点；暂停 MCU 时软件无法控制，恢复后超时会关断。

## 如何选最终系数

先用默认 PI、0.25 倍开始，按 K3 做一次验证。电流先保持原目标 2s，再增加 **0.1A** 保持 4s，总计 6s 后自动关断。参数 `cc_status.gains` 就是这一轮实际使用的系数。

屏幕显示：

- `OS%`：上升阶跃后的超调，相对 **0.1A 阶跃幅度**计算。例如峰值 1.12A、目标 1.10A，超调为 20%。
- `ERR`：末尾 1s 的目标减平均电流，单位 A。

Watch 还能查看 `cc_status.ripple`（末尾 1s 峰峰值，A）和 `cc_status.settling_ms`（相对阶跃时刻，进入 ±max(10mA, 目标的2%) 后不再离开的最后越界时间估计，单位 ms；结束前必须至少连续保持 500ms，否则为 -1）。`verify_valid` 为真才表示本轮验证完整结束；中途停止或故障不算有效验证。10ms 采样无法反映采样点之间的高频尖峰。

若误差收敛慢且波形平稳，可以逐档增加倍率并重新验证；若有明显超调、周期振荡或保护触发，应降低系数。PI 已满足要求时可保留 `Kd=0`；只有验证表明微分有帮助才采用 PID。最后在所需的多个负载、输入电压、电流点重测，按项目允许的超调、误差和稳定时间选择。自动生成的是待验证的起点，并不保证最佳或稳定。

### 自动识别不通过时手动验证

`CYCLE TOO FAST` 表示当前 10ms 采样对观测周期分辨率不足，不应直接删掉该判据来强行出系数。可提高实际采样速度并同步调整 `CC_PERIOD_MS`/`CC_MAX_GAP_MS` 后重测；或先使用以下手动验证入口，调较慢的外层恒流环：

1. 故障先按 K3 回到 IDLE，在关闭输出时修改 Watch：`cc_manual.kp`、`.ki`、`.kd`，以及工作点 `cc_manual_bias`（**DAC 伏特**，不是输出电压；默认按 8V 输出的理论值约 1.996V）。手动系数应从你希望测试的小系数开始。
2. 设置 `cc_apply_manual=1` 并继续运行，程序校验有限值和范围，进入 `M` 标记的手动结果页。此时 `KU/TU` 为 0，表示没有自动识别结果。
3. 按 K3 做同样的阶跃验证。修改 P/I/D、比较超调和误差，直到满足需求。手动页 K1 可在同一组系数的 `Kd=0` 与所填 `Kd` 间切换，K2 同样调倍率。

手动入口在 IDLE/READY 生效，运行中不会改变系数；负值、非有限值或 `Kp=0` 被拒绝。修改工作点和参数后必须继续运行让设置生效，再按实体 K3 启动。

## 参数定义和移植

实现使用**位置式、连续时间单位**，不是增量式系数，也不是 DAC 码值系数：

```text
e = Iset - Iout                                      [A]
integral += Ki * e * dt                              [DAC V]
d_filtered = lowpass((Iout - previous_Iout) / dt)      [A/s]
Vdac = bias - Kp*e - integral + Kd*d_filtered          [DAC V]
```

| 系数 | 单位 |
|---|---|
| Kp | DAC V / A |
| Ki | DAC V / (A·s) |
| Kd | DAC V·s / A |

`dt` 是新采样完成时间差，单位秒。积分跟踪实际限幅后的输出，抑制绝对饱和和 DAC 斜率限制引起的积分积累；微分只作用于测量，使用 `max(30ms, Kd/Kp/10)` 滤波时间常数。DAC 变化率限制为 0.5V/s，最低 DAC 按理论 12V 输出上限换算。

**电流不足应减小 DAC**，不能照搬正增益对象的输出符号。移植到主程序时，要同时移植 `verify_step()` 的离散算法、初始化积分、测量节拍、DAC 限幅与斜率限制。主程序当前采样调度加 OLED 阻塞并非本固件的 10ms 节拍，不能只把三个数填入当前空的 `App_ControlStep()` 就认为恒流已经完成。换用 DAC 码值、归一化输出或增量 PID 都需重新换算并验证。

自动系数采用理想继电器描述函数近似和经典 Ziegler–Nichols 系数：

```text
Ku ≈ 4*d/(π*a)        d=DAC扰动半幅[V]，a=电流峰峰值/2[A]
Tu = 平均完整周期[s]
PI:  Kp=0.45Ku    Ki=0.54Ku/Tu    Kd=0
PID: Kp=0.60Ku    Ki=1.20Ku/Tu    Kd=0.075Ku*Tu
```

迟滞、离散采样、非正弦波形及功率级非线性都会使此估计偏离真实临界点，因此设置质量判据并默认缩小系数，仍须验证。参考：[Åström/Hägglund 原始方法](https://www.sciencedirect.com/science/article/pii/0005109884900141)、[Zurich Instruments 的 PID 系数表](https://www.zhinst.com/sites/default/files/documents/2023-08/zi_whitepaper_principles_of_pid_controllers.pdf)。

## 波形导出

`cc_trace` 是 512 点 RAM 环形缓冲，约保存最后 5.12s，字段为 `ms/iout/setpoint/dac/state`。每次启动清计数，停止后保留；`dac` 是该采样处理后的实际写入命令，结束那一条会变为关断后的 3.1V。自动寻找工作点较久时前面的数据会被覆盖。

结束并确认 PA1 关闭后，在调试器中读取 `cc_trace_count`，并导出：

```gdb
p cc_trace_count
dump binary memory /tmp/cc_trace.bin &cc_trace[0] &cc_trace[512]
```

将读到的计数替换下面的 `640`，转换成按时间排列的 CSV：

```bash
python3 TEST_PID/trace_to_csv.py /tmp/cc_trace.bin --count 640 --output /tmp/cc_trace.csv
```

可用表格软件绘制 `time_s` 对 `iout_A/target_A`。32 位毫秒计时回绕由导出程序处理。

## 保护与已做验证

每轮四通道新采样后检查：Vin 低于 12.5V、Vout 超过 12V、Iout 超过 `min(2.3A, 基准目标+0.35A)` 即关断锁存；启动需 Vin≥13V。ADC 调用失败、任一 ADC 接近高端贴轨、非有限数据、输出期间采样间隔大于 25ms 也会关断。独立调参固件没有主程序的合闸过流屏蔽、3s 欠压延时或自动恢复。软件检测发生在采样时，不能代替台架限流和硬件保护；信号断线但 ADC 读数正常并不能完全识别。

已在主机执行 `python3 tests/run_cc_pid.py`，覆盖带时延的**人工慢对象**的识别与阶跃、计时回绕、量程/周期/幅值/占空比拒绝、保护锁存、控制方向、限速和积分抗饱和，以及手动入口。该对象不是本板实测模型；实际 LM2596 环路可能远快于它而触发 `CYCLE TOO FAST`。主程序和模块逻辑回归通过，Debug 全部目标构建通过。没有连接硬件、烧录或得到本板最终 PID 系数。
